# O83 Care - Case Architecture

Version: 1.0

---

# Purpose

Case คือหน่วยข้อมูลหลัก (Core Business Object) ของระบบ O83 Care

ทุกการดำเนินงานที่ต้องมีการติดตาม ตรวจสอบ หรือสามารถอ้างอิงย้อนหลังได้
ต้องถูกสร้างเป็น Case

Case ไม่ใช่ Ticket

Case ไม่ใช่ Work Order

Case คือ "เรื่องหนึ่งเรื่อง" ที่มีการเดินทางของตัวเองตั้งแต่เริ่มต้นจนสิ้นสุด

---

# Philosophy

ระบบไม่ได้มีหน้าที่เพียงเก็บข้อมูล

แต่มีหน้าที่เก็บ "ความเข้าใจ"

เมื่อเวลาผ่านไป

คนสามารถเปลี่ยน

กรรมการสามารถเปลี่ยน

บริษัทบริหารสามารถเปลี่ยน

ช่างสามารถเปลี่ยน

แต่ความเข้าใจขององค์กรต้องไม่สูญหาย

Case คือความทรงจำของโครงการ

---

# What Can Be A Case

ตัวอย่าง

✓ งานซ่อม

✓ งาน PM

✓ หนังสือราชการ

✓ งานผู้รับเหมา

✓ งาน Compliance

✓ งานกฎหมาย

✓ งานที่เกี่ยวข้องกับทรัพย์สินส่วนกลาง

✓ งานที่ต้องติดตาม

ตัวอย่างที่ไม่ใช่ Case

✗ ประกาศ

✗ ข่าวสาร

✗ เมนู

✗ เอกสารอ้างอิงทั่วไป

# Core Components

ทุก Case ต้องประกอบด้วย

## 1. Identity

Case ID

เช่น

CASE-2026-000123

Title

Case Type

Created Date

Current Status

PDCA Phase

---

## 2. Context

เหตุเกิดที่ไหน

ใครแจ้ง

วันที่เกิดเหตุ

วันที่รับแจ้ง

Property

Building

Floor

Location

Related Entity

---

## 3. Journey

Journey คือหัวใจของระบบ

Journey ต้องบอกได้ว่า

- เกิดอะไรขึ้น
- ใครทำ
- เมื่อไร
- ทำไม
- ผลลัพธ์คืออะไร

Journey ไม่ใช่เพียง Timeline

แต่เป็นประวัติการตัดสินใจทั้งหมดของ Case

---

## 4. Evidence

Evidence คือหลักฐาน

ไม่ใช่ไฟล์แนบ

Evidence อาจประกอบด้วย

- Before Photo
- During Photo
- After Photo
- Video
- Checklist
- Measurement
- Quotation
- Invoice
- Report
- Signature
- Official Document

Evidence ที่ต้องใช้จะแตกต่างกันตามประเภทของ Case

---

## 5. Collaboration

ผู้เกี่ยวข้องสามารถสื่อสารกันภายใน Case

Comment

Mention

Discussion

Decision

ทุกข้อความจะกลายเป็นส่วนหนึ่งของประวัติ Case

---

## 6. Next Action

ทุก Case ต้องตอบได้เสมอ

ใคร

ต้องทำอะไร

ภายในเมื่อไร

และกำลังรออะไร

หากไม่มี Next Action

แสดงว่า Case ไม่สามารถเดินต่อได้

---

## 7. Completion Rules

Case จะปิดได้

เมื่อเงื่อนไขครบเท่านั้น

เช่น

✓ หลักฐานครบ

✓ ตรวจรับแล้ว

✓ แจ้งผู้เกี่ยวข้องแล้ว

✓ ระยะติดตามครบ

Completion Rules แตกต่างกันในแต่ละประเภทของ Case

# Case Number

ตัวอย่าง

CASE-2026-000123

หลีกเลี่ยงการใช้รหัสย่อเฉพาะหน่วยงาน

เพื่อลดความซับซ้อนในการใช้งาน

---

# Transparency Principle

ทุกผู้มีสิทธิ์เข้าถึง Case

ต้องสามารถเข้าใจได้ทันทีว่า

- เกิดอะไรขึ้น
- ทำไมจึงเกิด
- ใครรับผิดชอบ
- ตอนนี้อยู่ขั้นตอนไหน
- มีหลักฐานอะไร
- ขั้นตอนต่อไปคืออะไร

โดยไม่ต้องโทรสอบถามบุคคลอื่น

---

# Knowledge Preservation

ข้อมูลทุกชิ้นใน Case

ถูกจัดเก็บเพื่อให้

คนที่ไม่ได้อยู่ในเหตุการณ์

สามารถเข้าใจเหตุการณ์ย้อนหลังได้

ระบบต้องช่วยรักษาความรู้ขององค์กร

ไม่ให้สูญหายไปพร้อมกับการเปลี่ยนคน

---

# Final Principle

Case ไม่ได้ถูกสร้างขึ้นเพื่อ "ปิดงาน"

Case ถูกสร้างขึ้นเพื่อ

แก้ไขปัญหา

ติดตามผล

สร้างความโปร่งใส

และเก็บรักษาความรู้ของโครงการในระยะยาว
