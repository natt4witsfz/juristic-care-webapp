# 1. ภาพรวมโครงการ

## 1.1 ชื่อระบบ

**Juristic Care — ระบบรับแจ้งและบริหารงานนิติบุคคล**

## 1.2 วัตถุประสงค์

1. รับแจ้งปัญหาจากลูกบ้านผ่าน Google Forms หรือหน้าแจ้งปัญหาของระบบ
2. รวมงานใหม่ไว้ใน Pool งานกลางเพื่อป้องกันงานตกหล่น
3. ให้ผู้ดูแลมอบหมายงาน หรือให้เจ้าหน้าที่หยิบงานไปดำเนินการเอง

5. ให้ลูกบ้านติดตามความคืบหน้าของปัญหาที่แจ้งได้
6. สรุปภาพรวมประสิทธิภาพการทำงานของนิติบุคคล

# 2. ระบบการทำงาน

## 2.1 บทบาทและสิทธิ์ผู้ใช้งาน

### A. ผู้ดูแลระบบ (Admin)

สามารถ:

- ดูงานทั้งหมดในระบบ
- ดู Pool งานกลาง
- สร้างงานใหม่
- มอบหมายงานให้เจ้าหน้าที่
- เปลี่ยนสถานะงาน
- ดูรายชื่อผู้ใช้งานและทีมงาน
- ดู Dashboard ภาพรวม
- ดูงานของห้องต่าง ๆ

ข้อเสนอสำหรับระบบจริง:

- เพิ่ม/ลบ/ระงับผู้ใช้งาน
- ตั้งค่าประเภทงานและ SLA
- แก้ไขข้อมูลห้อง
- ดาวน์โหลดรายงาน
- ตรวจสอบประวัติการแก้ไขงาน

### B. เจ้าหน้าที่ (Staff)

สามารถ:

- ดูงานที่ได้รับมอบหมาย
- ดูงานใน Pool กลาง
- กดรับงานจาก Pool
- เปลี่ยนสถานะงานที่รับผิดชอบ
- ดูรายละเอียดผู้แจ้งและพื้นที่เกิดเหตุ

ข้อเสนอสำหรับระบบจริง:

- เพิ่มรูปก่อนและหลังดำเนินการ
- เพิ่มบันทึกความคืบหน้า
- ส่งงานต่อให้เจ้าหน้าที่คนอื่น
- ขออนุมัติค่าใช้จ่ายหรืออะไหล่
- บันทึกเวลาที่เริ่มและจบงาน

### C. ลูกบ้าน (Resident)

สามารถ:

- Login ด้วยเลขห้องและรหัสผ่าน
- ดูงานที่ห้องของตนเองแจ้ง
- ดูสถานะและรายละเอียดงาน
- ดูงานส่วนกลางที่กำหนดให้เปิดเผย

ข้อเสนอสำหรับระบบจริง:

- แจ้งปัญหาจากใน WebApp
- แนบรูปหรือวิดีโอ
- สนทนากับเจ้าหน้าที่
- ยืนยันว่าปัญหาได้รับการแก้ไขแล้ว
- ให้คะแนนและความคิดเห็นหลังปิดงาน

## 2.4 วงจรชีวิตของงาน

### สถานะปัจจุบัน

1. **รอรับงาน (Waiting)**  
   งานใหม่ที่ยังไม่มีผู้รับผิดชอบ หรือกำลังรอการดำเนินการ

2. **กำลังดำเนินการ (In Progress)**  
   งานที่มีผู้รับผิดชอบและเริ่มดำเนินการแล้ว

3. **เสร็จสิ้น (Done)**  
   งานที่ดำเนินการเสร็จแล้ว

### สถานะที่แนะนำสำหรับระบบจริง

1. รับแจ้งแล้ว
2. รอตรวจสอบ
3. รอมอบหมาย
4. รับงานแล้ว
5. กำลังดำเนินการ
6. รออะไหล่/ผู้รับเหมา
7. รอยืนยันจากผู้แจ้ง
8. เสร็จสิ้น
9. ยกเลิก
10. เปิดงานใหม่อีกครั้ง

## 2.7 Pool งานกลาง

### หลักการ

- งานที่ยังไม่มีผู้รับผิดชอบจะอยู่ใน Pool กลาง
- Admin สามารถมอบหมายงานให้เจ้าหน้าที่
- Staff สามารถกด “รับงานนี้”
- เมื่อรับงาน ระบบเปลี่ยนสถานะเป็น “กำลังดำเนินการ”
- ชื่อผู้รับงานถูกบันทึกเป็นผู้รับผิดชอบ

### กฎที่ควรกำหนดเพิ่ม

- เจ้าหน้าที่หนึ่งคนรับงานพร้อมกันได้สูงสุดกี่งาน
- งานฉุกเฉินอนุญาตให้ใครรับได้บ้าง
- งานบางประเภทต้องส่งให้ทีมเฉพาะหรือไม่
- หากไม่มีคนรับภายใน SLA ให้แจ้งเตือนใคร
- Admin สามารถดึงงานกลับเข้า Pool ได้หรือไม่

## 2.8 การสร้างและมอบหมายงาน

- หัวข้องาน

- ประเภท
- ระดับความเร่งด่วน
- ผู้รับผิดชอบ
- รายละเอียด

พฤติกรรม:

- หากเลือกผู้รับผิดชอบ สถานะเริ่มต้นเป็น “กำลังดำเนินการ”
- หากไม่เลือกผู้รับผิดชอบ งานจะเข้า Pool และมีสถานะ “รอรับงาน”

- วันครบกำหนด

## 2.15 Login และความปลอดภัย

### Mock Up ปัจจุบัน

- Login ด้วยเลขห้องและรหัสผ่าน
- มีโหมดตั้งรหัสผ่านครั้งแรก
- Session เก็บใน `sessionStorage`
- ข้อมูลผู้ใช้และรหัสผ่านเป็นข้อมูลจำลองใน JavaScript
- ไม่มี Backend และยังไม่เหมาะสำหรับข้อมูลจริง

### ระบบ Production ที่แนะนำ

- เก็บรหัสผ่านแบบ Hash
- ใช้ HTTPS
- Session หรือ JWT ที่มีวันหมดอายุ
- จำกัดจำนวนครั้งการ Login ผิด
- OTP สำหรับตั้งรหัสผ่านครั้งแรก
- Reset Password ผ่านเบอร์โทรหรือ Email ที่ลงทะเบียน
- Audit Log สำหรับการแก้ไขข้อมูลสำคัญ
- สิทธิ์การเข้าถึงข้อมูลตามบทบาทและเลขห้อง
- สำรองข้อมูลและนโยบายเก็บรักษาข้อมูล

## 2.16 Device Detection

ระบบตรวจว่าเป็น Mobile หรือ Desktop จาก:

1. User Agent เช่น Android หรือ iPhone
2. จำนวนจุดสัมผัส
3. ขนาดหน้าจอไม่เกิน 820px
4. Tablet/Touch device ขนาดไม่เกิน 1024px

สามารถบังคับทดสอบได้:

- `?device=mobile`
- `?device=desktop`

ข้อควรทราบ:

- ควรใช้ Responsive Design เป็นหลัก
- Device Detection ใช้เพื่อเลือก UX เริ่มต้น
- ผู้ใช้ควรยังสามารถใช้งานได้เมื่อย่อหรือขยายหน้าจอ

## 3.1 แนวคิดการออกแบบ

อ้างอิงแนวคิดจากระบบ Traffy Fondue:

`เห็นภาพรวมเร็ว → กรองงานง่าย → เปิดรายละเอียด → ลงมือดำเนินการ`

บุคลิกของระบบ:

- น่าเชื่อถือ
- สะอาด
- เป็นมิตร
- ดูเป็นระบบ
- เห็นสถานะได้รวดเร็ว
- ลดจำนวนขั้นตอนในการรับและอัปเดตงาน

## 3.2 โครงสร้างเมนู

### Desktop

ใช้ Sidebar ด้านซ้าย:

1. ภาพรวม
2. Pool งานกลาง
3. งานของฉัน
4. งานของห้อง
5. ทีมงาน — Admin เท่านั้น
6. Google Forms
7. ออกจากระบบ

### Mobile

ใช้ Bottom Navigation:

1. ภาพรวม
2. Pool
3. งานฉัน
4. ห้องฉัน
5. ทีม — Admin เท่านั้น

ปุ่มสร้างงานเป็น Floating Action Button มุมล่างขวา

## 3.3 หน้า Login

### Desktop Layout

- ด้านซ้าย: Brand, ข้อความแนะนำระบบ, สถิติ และภาพตกแต่ง
- ด้านขวา: ฟอร์ม Login

องค์ประกอบ:

- Logo และชื่อ Juristic Care
- สถานะ “ระบบพร้อมให้บริการ”
- ช่องเลขห้อง
- ช่องรหัสผ่าน
- ปุ่มแสดง/ซ่อนรหัสผ่าน
- ปุ่มเข้าสู่ระบบ
- ลิงก์ตั้งรหัสผ่านครั้งแรก
- ปุ่มเข้าบัญชีทดลอง
- ข้อความนโยบายข้อมูล

### Mobile Layout

- ซ่อนส่วนภาพประชาสัมพันธ์ด้านซ้าย
- แสดง Logo ด้านบน
- ฟอร์มกว้างเต็มพื้นที่
- ปุ่มมีความสูงเหมาะกับการแตะ

ข้อความที่แก้ไขได้:

- Headline: `[ทุกปัญหาในบ้าน มีคนรับช่วงต่อ]`
- Description: `[แจ้ง ติดตาม และจัดการงานของนิติบุคคลในที่เดียว]`
- Privacy: `[ข้อมูลของคุณถูกใช้เพื่อการบริหารอาคารเท่านั้น]`

## 3.4 หน้า Dashboard

ลำดับการมองเห็น:

1. คำทักทายและวันที่
2. จำนวนงานสำคัญ
3. งานที่ต้องดูแล
4. ความเคลื่อนไหวล่าสุด
5. สรุปประเภทปัญหา

### Status Cards

- รอรับงาน — สีเหลือง/ส้ม
- กำลังดำเนินการ — สีน้ำเงิน
- เสร็จสิ้น — สีเขียว
- คะแนนความพึงพอใจ — สีม่วง

พฤติกรรม:

- กด Card เพื่อไปหน้ารายการงานตามสถานะ
- จำนวนเปลี่ยนตามข้อมูลในระบบ

### Desktop

- Status Cards 4 ช่องต่อแถว
- รายการงานและ Activity แสดงคู่กัน
- แสดงข้อมูลในแต่ละแถวมากกว่า Mobile

### Mobile

- Status Cards 2 ช่องต่อแถว
- ซ่อน Activity เพื่อลดความหนาแน่น
- รายการงานเป็นการ์ดขนาดกระชับ
- ใช้ Bottom Navigation

## 3.5 หน้ารายการงาน

องค์ประกอบ:

- ช่องค้นหา
- ตัวกรองสถานะ
- ตัวกรองประเภท
- จำนวนผลลัพธ์
- รายการงาน
- Empty State เมื่อไม่มีข้อมูล

ข้อมูลในรายการ:

- Icon ประเภทงาน
- หัวข้องาน
- เลขที่งาน
- เลขห้องหรือพื้นที่
- เวลา
- ความเร่งด่วน
- ผู้รับผิดชอบ
- สถานะ

### Mobile

แสดงข้อมูลสำคัญเท่านั้น:

- Icon
- หัวข้อ
- เลขที่งาน/ห้อง/เวลา
- สถานะหรือปุ่มรับงาน

ข้อมูลรองถูกซ่อนและดูได้ในหน้ารายละเอียด

## 3.6 หน้า Pool งานกลาง

- แสดงเฉพาะงานที่ยังไม่มีผู้รับผิดชอบ
- มีจำนวนงานบน Badge ของเมนู
- ปุ่ม “รับงานนี้” แสดงแทนสถานะ
- หลังรับงาน รายการจะออกจาก Pool

คำถาม UX ที่ต้องตัดสินใจ:

- ต้องแสดงผู้ที่กำลังกดรับงานพร้อมกันหรือไม่
- ต้องมีหน้าต่างยืนยันก่อนรับงานหรือไม่
- งานฉุกเฉินต้องมีสีหรือเสียงแจ้งเตือนเพิ่มเติมหรือไม่

## 3.7 หน้ารายละเอียดงาน

เปิดเป็น Modal บน Desktop และ Bottom Sheet บน Mobile

ข้อมูล:

- เลขที่งาน
- หัวข้องาน
- สถานะ
- รายละเอียด
- พื้นที่/เลขห้อง
- ประเภท
- ผู้แจ้ง
- วันที่และเวลา
- ความเร่งด่วน
- ผู้รับผิดชอบ

เจ้าหน้าที่และ Admin สามารถเปลี่ยนสถานะได้

สิ่งที่เสนอให้เพิ่ม:

- Timeline
- รูปภาพก่อน/หลัง
- ความคิดเห็น
- พิกัดหรือแผนที่อาคาร
- ค่าใช้จ่าย
- ปุ่มโทรหาผู้แจ้ง
- ปุ่มส่งต่อหรือมอบหมายใหม่

## 3.8 ฟอร์มสร้างงาน

Desktop:

- Modal กลางหน้าจอ
- ฟิลด์แบบ 2 คอลัมน์

Mobile:

- Bottom Sheet เต็มความกว้าง
- ฟิลด์เรียง 1 คอลัมน์
- ปุ่ม Action อยู่ด้านล่าง

Validation ที่ควรมี:

- หัวข้องานห้ามว่าง
- เลขห้องหรือพื้นที่ห้ามว่าง
- ตรวจรูปแบบเลขห้อง
- จำกัดขนาดไฟล์แนบ
- เตือนเมื่อพบงานคล้ายกัน
- เตือนเมื่อเลือกความเร่งด่วน “ฉุกเฉิน”

## 3.9 หน้าทีมงาน

ข้อมูลปัจจุบัน:

- สมาชิกทั้งหมด
- พร้อมรับงาน
- กำลังปฏิบัติงาน
- ไม่อยู่
- รายชื่อ

- สถานะพร้อมใช้งาน

ข้อเสนอสำหรับระบบจริง:

- จำนวนงานปัจจุบันของแต่ละคน

# 5. สถาปัตยกรรมระบบที่แนะนำ

## ตัวเลือก A: Google Workspace เหมาะกับ 30 Users

- Frontend: WebApp ปัจจุบัน
- Authentication: Google Apps Script + OTP/รหัสห้อง
- Database เริ่มต้น: Google Sheets
- Intake: Google Forms
- File Storage: Google Drive
- Automation: Apps Script
- Notification: LINE Messaging API หรือ Email

ข้อดี:

- ค่าใช้จ่ายต่ำ
- ดูแลไม่ซับซ้อน
- เชื่อม Google Forms ได้ตรง

ข้อจำกัด:

- ไม่เหมาะกับข้อมูลจำนวนมากหรือ Transaction ซับซ้อน
- Permission และความปลอดภัยต้องออกแบบอย่างระมัดระวัง

## ตัวเลือก B: Web Application เต็มรูปแบบ

- Frontend: React/Next.js หรือเทคโนโลยีที่เลือก
- Backend: Node.js
- Database: PostgreSQL
- Authentication: Supabase Auth, Firebase Auth หรือระบบภายใน
- File Storage: Cloud Storage
- Notification: LINE/Email/Push Notification

ข้อดี:

- ขยายระบบง่าย
- ปลอดภัยและจัดการข้อมูลพร้อมกันได้ดีกว่า
- เหมาะกับหลายอาคาร

ข้อจำกัด:

- ค่าใช้จ่ายและการดูแลสูงขึ้น

# 7. Acceptance Criteria ฉบับเริ่มต้น

ระบบถือว่าพร้อมใช้งานระยะแรกเมื่อ:

1. ลูกบ้าน Login และเห็นเฉพาะข้อมูลที่ได้รับอนุญาต
2. ข้อมูลจาก Google Forms เข้า Pool ภายในเวลาที่กำหนด
3. Admin มอบหมายงานได้
4. Staff รับและอัปเดตงานได้
5. ลูกบ้านติดตามสถานะงานของห้องได้
6. ทุกการเปลี่ยนสถานะมีประวัติผู้แก้ไขและเวลา
7. งานเกิน SLA มีการแจ้งเตือน
8. รองรับ Mobile และ Desktop
9. สำรองข้อมูลและกู้คืนได้
10. รหัสผ่านและข้อมูลส่วนบุคคลไม่ถูกเก็บเป็น Plain Text
